# Changelog

Selected milestones in the development of NovaLiveSystem and its public research showcase.

## November 10, 2026 - response provenance and running-stack diagnostics

- Record the producer of every reply, the local language engine or a stated fallback, with a request identifier shown
  beside the message in the app.
- Return one reply per user turn; only the returned reply enters Nova's memory, and failed generations are kept as
  diagnostics rather than as Nova's words.
- Keep past failure notices out of recalled memory on the index that feeds recall, while preserving historical records.
- Add an operator-only running-stack view: registered regions, language-engine reachability, the four channels of
  Nova's heartbeat with their freshness, and the producer of the last reply, observed without starting a second system.
- Retain the language engine's lifecycle and output logs so an unexpected exit is observable.
- Open the [public R&D board](public-board.md) as the record of what is built, what is being proven, and what comes
  next.

## November 9, 2026 - capability, funding and founder voice

- Publish a concise capability and funding case as the primary evidence page.
- Restore the founder's greeting, developing-mind framing, lived origin and cognitive-cultivation purpose.
- Present the architecture through implemented roles, current evidence and continuing research.
- Restore the Asyncio Neural Bypass story as an architecture-wide engineering milestone.

## October 2026 - a clearer public research foundation

- Reorganize the repository around architecture, research, evidence, development and collaboration.
- Rewrite README and About around Spark's voice, the second-brain origin, ABI and cognitive cultivation.
- Add a dedicated papers page for Spark's two December 2025 preprints.
- Publish a conceptual architecture, capability review and separate routes for funding, commercial and research
  inquiries.
- Establish protected publication review so public wording, privacy and ownership are checked before release.

## December 2025 - routing, models and the first product

### December 14 - EchoCopi release

- Bring EchoCopi, SparkPlugged's standalone persistent-memory product, to commercial release.
- Add the first public showcase assets and product-supporting documentation.

### December 13 - Nova Mind v1

- Complete the Nova Mind v1 interoceptive training program across internal-state and architecture domains.
- Build a 10,000-sample curriculum spanning interoception, architecture, prediction, metacognition and relational
  reasoning.
- Add five synthetic-data generators to support continued curriculum development.

### December 10–12 - Asyncio Neural Bypass

- Rebuild routing around an asynchronous core while preserving compatibility for connected callers.
- Extend the migration across BridgeEngine, memory, language, presence, pulse, learning, vision and education paths.
- Find and repair re-entry deadlocks, coroutine-cache reuse, unawaited handlers and event-loop boundary conflicts.
- Record the resulting engineering pattern: concurrency is a contract across the integrated architecture.

Read the full [asynchronous-routing development story](async-routing-history.md).

## November 2025 - control, memory and training infrastructure

- Add a GRPO training path designed for a consumer RTX 4050-class GPU.
- Repair recursive memory growth in high-load LanguageEngine thought chains.
- Rewrite BridgeEngine routing to remove circular dependencies and strengthen central coordination.
- Establish Stage10 grounding and system-discipline datasets, a probe-per-dataset rule and a dataset registry with
  validation and promotion steps.
- Create the first NovaLiveSystem showcase repository and automated drift-regression suite.
- Remove obsolete model artifacts and dead legacy code as the architecture consolidated.

## October 2025 - from the pre-Git system to trained models

- Import the pre-Git NovaLiveSystem into source control as a 158-file working system spanning core processors, brain
  regions and runtime tools.
- Lock the anatomical architecture, wire nine core regions and establish the EventBus, tri-heartbeat system and
  RiverPulse living-memory stream.
- Complete the first supervised fine-tuning runs, then advance through grammar, fluency and continued-training stages.
- Establish validation-first training, warm-start refinement and a quality-over-quantity dataset strategy.
- Restructure the repository into `nova/` for the cognitive architecture and `tools/` for runtime and infrastructure.
- Expand the conversational curriculum and record successive Nova model-training runs.

## Spring–summer 2025 - mobile-first genesis

- Begin NovaLiveSystem through architecture mapping and concept validation on two iPhones and an iPad.
- Expand the build onto a PC environment as the mobile-first system grows.
